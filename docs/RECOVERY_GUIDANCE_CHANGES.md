# Flight recovery, guidance and outside view

Implemented 2026-10-20.

- Recover Flight is a main-menu destination alongside Single Player, Tutorial, Challenges and Settings. It supports cloud resume/discard and `.acs` file import, including offline file recovery.
- New version 1.1 saves include session/route configuration, physics position and attitude, engine state, fuel, systems, failures/cascade state, component damage, navigation progress, simulation time, and AP/FD configuration. Existing version 1.0 physics saves remain supported. Data that an older save never recorded cannot be reconstructed exactly.
- Recovery validates the snapshot and aircraft before starting a fresh flight component. This prevents input buffers, UI state, or the departure spawn from overwriting the restored aircraft. Waypoint progress is synchronized to the navigation service. Downloaded saves preserve Chinese text using UTF-8 and still read legacy files.
- VNAV now receives the active waypoint altitude and uses altitude capture/hold. Selected VS tapers near the altitude and becomes zero within the capture tolerance, with small internal corrections to counter drift. The older VNAV regression now explicitly arms VNAV rather than assuming LNAV enables it.
- Physics and outside scenery share surveyed runway geometry where available, including LAX's true headings and reciprocal thresholds. Unknown runway requests no longer silently select a different strip. ILS declines designator-only headings and displays invalid LOC/GS references rather than fake centered diamonds. Known frequency lookups normalize ICAO/IATA aliases.
- PFDs show tuned localizer/glideslope dots and magenta diamonds independently of AP engagement. The F/D computes the same pitch/roll targets as the autopilot while leaving manual controls untouched when AP is off. Its magenta cross moves with target error and disappears when F/D is off. The pictured 737 switch is labeled F/D, moves up for on and down for off, and no longer shows INOP; A/T remains a separate control.
- CWS retains stability control and pilot steering override. Selecting CWS switches both guidance and FD to stability commands, so the bars agree with the controller rather than retaining LNAV/APP targets.
- Outside scenery no longer waits for runway selection or ground-package loading. Valid GPS coordinates initialize the view; when runway geometry is unavailable, terrain uses an aircraft-position reference without inventing a runway. WebGL initialization failure produces a translated explanation.
- New recovery copy, errors, terrain status and instrument accessibility labels have Chinese translations.
- APP uses an explicit Flight Computer → Approach reference. Select the airport/runway there, read its course and NAV1 frequency, then enter and tune that frequency on the bottom central console. Ground scenery geometry never silently becomes the APP reference, and changing NAV1 never selects another runway. Missing references and adjacent/wrong channels leave LOC/GS unavailable. The selected approach and tuning are included in new saves.

Validation: 371 Node tests passed; expanded autopilot matrix passed; AIP smoke checks passed 6 cases with 1 skipped for existing US route-data coverage; production build passed with existing large-bundle warnings. New modules, Approach page, NAV1 controls, translations and the outside scene pass focused ESLint. Repository-wide lint still fails on the existing backlog.

Browser playthroughs and authenticated cloud round trips remain manual checks. SVG rendering tests verify actual F/D lever orientation, enabled command bars, ILS scales/diamonds and Chinese labels. Matrix cases with estimated headings assert that ILS stays unavailable; these cases are not evidence of supported precision approaches at those airports.
